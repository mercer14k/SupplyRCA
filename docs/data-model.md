# Data dictionary and provenance

The input is an uncompressed JSON object with `schema_version: "1"` and five nonempty arrays under `tables`. A committed `.json.gz` sample is compressed only for repository size; uploads deliberately do not accept compressed bodies or archives. Unknown tables/record fields are rejected. JSON Schemas are generated from Pydantic into `data/schemas`.

Every record has `id` (stable, globally unique within a bundle), `source_id` (upstream dataset identifier), `ingested_at` (timestamp), `validation_status: "valid"`, and optional `lineage` string metadata. The outer imported dataset ID identifies an immutable snapshot and can differ from upstream `source_id`. Validation reports record actual validation time and a SHA-256 of canonical original input. Generated records use a fixed logical ingestion timestamp for reproducibility, not the wall-clock generation time.

| Table | Grain | Fields / units |
|---|---|---|
| suppliers | Supplier | `name`, `country`; four fictional organizations in the sample |
| demand | Date × SKU × market | `demand`, `forecast`, `fulfilled` in units; `supplier_id` |
| inventory | Same daily grain | `opening`, `received`, `shipped`, `closing` in units |
| purchase_orders | Daily replenishment/receipt cohort | `ordered`, `received` in units; `lead_days`, `promised_lead_days` in days |
| shipments | Daily transportation cohort | `transit_days`, `planned_transit_days` in days; `po_id` |

`date` is an ISO calendar date without timezone. Records must align on date, SKU, market and supplier. Demand fulfillment must equal inventory shipments. PO receipts must equal inventory receipts. Opening + receipts − shipments = closing. Each SKU–market's opening must equal the previous record's closing. Missing calendar days are not fabricated; analysis checks requested daily coverage. The current ingestion validator does not assert a complete calendar outside the requested investigation.

Daily purchase orders are simplified cohorts; actual order creation, partial receipt events, backorders, cancellations and transport legs are not independently modeled. `lead_days` and `transit_days` are observed cohort attributes, not durations inferred from a detailed event ledger. Orders are generated by a bounded base-stock policy and lost sales are not carried forward. Do not treat the simulator as an ERP digital twin.

## KPI definitions

| KPI | Definition | Direction of deterioration |
|---|---|---|
| Fill rate | sum(fulfilled) / sum(demand) | Down |
| Stockout rate | Count(demand > fulfilled and demand > 0) / count(demand > 0) | Up |
| Lead time | Mean observed PO cohort lead_days; equally weighted by cohort | Up |
| Inventory cover | sum(closing) / sum(demand) over the same daily rows | Up |
| Forecast accuracy | 1 − sum(abs(forecast − demand)) / sum(demand) | Down |

Inventory cover is average daily stock divided by average daily demand, expressed in days. It is a relative diagnostic for excess inventory, not inventory valuation or a policy-specific excess-unit estimate. Forecast accuracy is `1 − WAPE`, may be negative, and is never clipped to hide severe errors. Zero denominators return undefined; investigations abstain with a typed error. All ratios aggregate numerator/denominator first.

## Seeded truth and edge cases

Default seed 42 generates 731 days for eight SKUs across three markets, plus four supplier masters: 23,396 records. Each SKU has five disjoint 21-day failures: reduced supplier receipts, transportation delays, unplanned demand increase, underforecasting, and overforecasting. Eight × five = 40 known incidents. The seed controls random demand, lead-time variation and transit jitter. Scenarios include leap day, weekends, stock depletion, partial receipts, recovery after disruption, integer zero receipt quantities and forecast bias.

`ground_truth.json` stores incident ID, SKU, supplier, market, start/end, expected cause and KPI. Only the evaluation harness reads it. Alert discovery uses rolling observations, so its alert count and start dates need not equal the seeded event labels. Malformed, duplicate, zero-denominator, missing-evidence and continuity cases are covered by tests; `invalid-bundle.json` is an intentionally invalid small import for the UI.

The SHA-256 reports identify source snapshots and deterministic computation payloads. PostgreSQL stores validated snapshots, quarantine payloads, investigations, and review events. See `packages/supplyrca/data/store.py` for the initial schema. Initial tables are created idempotently; schema migrations are a documented next step.
